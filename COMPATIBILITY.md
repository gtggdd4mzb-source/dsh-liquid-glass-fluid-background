# Compatibility evidence

Validation date: 2026-11-27. Current plugin: **0.6.2**. Target: installed **DeepSeek Harness Desktop 0.2.2-rc.5**, containing **@deepseek-ai/dsh 0.2.2-rc.5** and **@deepseek-ai/cordis 4.1.0**. The unrelated global CLI was 0.1.2-rc.1 and was not used as the target.

Verified:

- 0.5.0 color/optics suite: five scenario groups verify live speed and all flow modes, pause/zero amplitude, palette/HEX persistence, brightness ordering, untrusted color/range normalization, bounded backdrop-only filters, pointer lights, forced colors and exact optical cleanup. A zero-blur, zero-highlight grid changes under refraction and restores byte-for-byte on renderer disposal.
- 0.5.0 native Windows: installed client hash matched the build. The new studio loaded in the existing Desktop process; speed was set to 1.60×, water flow selected, a HEX color edited, blur set to 6 px and edge refraction to 34 px through the actual desktop controls. The running task was retained; the application's exit warning was cancelled. Existing startup settings remained available.
- Node host tests: exactly one safe classic script per boot table, fresh tables, browserless import, no removed client-runtime imports, lifecycle disposer and bundle manifest.
- Actual target-host Cordis: mount plugin, collect its `webserver/index-inject` row, render using the host's own `renderIndexInjections`, dispose the plugin, and confirm the row listener is gone.
- Clean isolated DSH_HOME: install the tarball using the Desktop-bundled CLI, verify the composed bundle row and installed client hash, start the actual Web frontend, open the Plugins page, and confirm version 0.3.0 and the running component. Disable and re-enable through the host's own switch; verify UI removal and remount with no frontend exceptions. No account or model request was needed.
- Edge headless browser: eleven scenarios covering boot timing, computed surface discovery, independent switches, persistence, keyboard focus, dark theme, reduced motion, forced colors, repeat injection, client disable/re-enable cleanup, invalid settings, cross-window sync, mobile bounds and denied storage. The new regression loads dark host CSS after the skin and also writes an inline base token, then confirms transparency while enabled and the original token on disable.
- Actual native Windows Desktop: upgraded the local plugin, inspected the new controls, restored the defaults, switched light/dark through Harness settings, and toggled the backdrop off/on. The dark center panel now reveals the gradient. No private screenshots or conversations were published for this check.
- Light/dark fixture previews were inspected visually. They are labeled as fixtures, not application screenshots.
- Startup browser checks: seven scenarios cover early/client handoff without duplicate overlays, hard timeout with paused CSS animations, no repeat on plugin remount, persistent startup toggle, replay, Escape/Skip, live dark-theme adoption, scope disposal, reduced-motion autoplay suppression/static replay, and failure isolation. Light/dark startup screenshots were visually inspected.
- Native Windows 0.5.0: the installed client hash matched the built file. Relaunched the actual Desktop application, inspected the startup toggle and replay button, replayed the whale animation on screen, and confirmed it automatically returned to the working application. The user's existing glass preferences were preserved.
- 0.6.0 session-design correction: the browser fixture no longer contains plugin-owned conversation markers. The client now discovers the real editor, composer, scrollable transcript, header, tabs and right-aligned user bubbles in the host DOM; the session skin remains independent of the glass master switch and removes only its own markers when disabled.
- Native Windows 0.6.0: the existing Desktop process (0.2.2-rc.5) loaded the session settings and already-installed 0.6.0. The live conversation DOM exposed none of the fixture's `data-conversation-*` markers, confirming why the prior session skin was incomplete. Clicking empty transcript space produced a visible ripple in the actual Harness window. The new DOM discovery implementation still requires a fresh real-window check after reinstall.

- 0.6.2 native composer correction: a host-shaped regression with nested wrappers verifies only the native card receives the composer skin, preserves width/padding, excludes wrapper/child glass surfaces, and survives 390/760/1280/1536 widths, tall drafts, card replacement, toggles, runtime replacement and disposal.
- Native Windows 0.6.2 runtime: patched built files were applied to the existing installed 0.6.0 package and remounted through the host plugin switch. The live input card had one surface after switching to another existing conversation, maximizing/restoring, and returning to the original conversation. Package-manager upgrade to 0.6.2 was not used for this check; no private desktop captures or conversations are included in the release.

Scope: this evidence verifies clean installation, real-host Web startup, native Windows Desktop display, plugin management and browser behavior. It does not claim a tour of every authenticated DSH screen or compatibility with every other installed theme, future Harness version, operating system or browser. Surface detection intentionally has a bounded budget and may leave unmatched regions unstyled.
